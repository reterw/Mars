# 04｜将研究资料转为仿真模型：参数、情景与验证路线

[返回研究总览](README.md)

> 本文是基于前三份专题研究提出的**建模建议**，不是已实现的软件、已校准的火星生产模型或任务安全标准。文中明确标注的示例值仅用于演示。原始证据见 [01](01-mars-resources-and-sites.md)、[02](02-agriculture-nutrition-and-loops.md)、[03](03-synthetic-food-and-feedstocks.md)，文献编号沿用各专题。

## 1. 仿真器首先应该回答什么

相比直接回答“哪个技术最好”，先回答可检查的问题：

1. 在指定人数、地点、季节和初始物资下，能否持续提供完整营养？
2. 最先耗尽的是水、能量、油脂、某种营养盐、种子，还是维修件？
3. 哪些产能依赖地球补给，哪些真正由火星资源支持？
4. 矿井、温室或反应器失效多久后会造成供应缺口？
5. 增加种植层数或反应器容量后，电力、散热和操作人力是否反而成为瓶颈？
6. 资源未知量改变后，候选场址或技术路线的优劣是否反转？

**不建议的目标：** 只最大化鲜菜重量、只最小化温室占地、或把所有自给程度折算为一个“闭合率”。

## 2. 统一证据字段，而非统一成一个可信度分数

每个参数至少需要以下信息。缺少关键边界时，可以用于研究比较，但不应自动成为生产模型默认值。

| 字段 | 含义 | 示例或规则 |
|---|---|---|
| `parameter_id` | 唯一参数标识 | `eden_2018_edible_fresh_mass` |
| `value` / `range` | 原始数值或区间 | 区间若是情景，不伪装成统计置信区间 |
| `unit` | 明确单位 | `kg_fresh`、`kg_dry`、`kWh`、`earth_day`、`sol` |
| `quantity_basis` | 数值分母与物质基准 | 每种植平方米、每公斤合格食品、每公斤 H2 的 COD 当量等 |
| `boundary` | 系统包含和排除的单元 | 仅照明；培养加下游；完整基地等 |
| `environment` | 实验环境 | 火星原位、地球温室、ISS 微重力、人工低压气氛 |
| `organism_or_material` | 品种、菌株或原料 | 不只写“生菜”“蛋白”或“土壤” |
| `conditions` | 温压、光照、配方、规模 | 未读取到的条件写未知 |
| `space_time_scope` | 地点、时间段和支持尺度 | 一个样品与整个地区不可等同 |
| `evidence_kind` | 证据性质 | 使用下表的标签，不由刊物名推定成熟度 |
| `access_level` | 实際阅读层级 | 全文相关章节、摘要、官方概述、元数据 |
| `source_ids` | 文献或数据来源 | `A07`；可关联多个但应说明各自支持什么 |
| `locator` | 出处定位 | Table 4、Fig. 1、摘要、产品元数据字段 |
| `uncertainty` | 误差、情景范围或未知 | 区分标准误、标准差、模型误差和人为上下界 |
| `status` | 在模型中的使用状态 | 原样记录、换算结果、待标定、禁止作默认值 |
| `retrieved_on` / `version` | 检索日期与版本 | 动态监管清单和地图必须保留版本 |

建议的 `evidence_kind`：

- `mars_in_situ`：火星当地仪器观测或工程实验；
- `orbital_inference`：轨道数据及解释；
- `earth_experiment`：地球实验或地面类比；
- `space_experiment`：近地空间实验，与火星当地实验分开；
- `model_estimate`：有明确方法的模型估计；
- `review_synthesis`：综述或评论转述，必要时继续找原始研究；
- `official_reference`：官方营养标准、任务概述、数据说明；
- `regulatory_record`：特定产品和工艺的监管记录；
- `company_claim`：企业披露，不能代替独立实测；
- `design_assumption`：为场景运行设置的假设；
- `unknown`：暂缺依据。

一次实验可以产生多个参数，性质不一定相同。例如培养数据属于地球实验，论文中对火星设备质量的外推仍属于模型。**不要为整篇论文赋一个标签后无差别继承到所有数字。**

## 3. 最小模块划分

| 模块 | 输入 | 输出 | 不能隐藏的约束 |
|---|---|---|---|
| 地点与气候 | 坐标、季节、尘埃情景、地形与数据版本 | 温压、可用辐照、资源证据及不确定性 | 插值结果不是现场实测；冬季和尘暴不能由年平均代替 |
| 水资源开采 | 设备、原料品位、埋深、电热、作业时间 | 原水、杂质、尾料 | 资源总量不等于产能；覆土、停机和热损失 |
| 水处理 | 不同来源原水、耗材、电热 | 合格水、浓缩液、残渣 | 按水源区分质量、回收率和处理负荷 |
| 气体与化工 | 原料气、水、能源、催化剂 | CO2、N2、H2、O2、可用氮源等库存 | 采集、压缩、分离、吹扫和质量标准 |
| 农业 | 品种、面积、光照、根区、CO2、水和盐 | 鲜/干可食物、残余物、气体、水蒸气 | 生长阶段、周转、种源、病害和人工操作 |
| 食品制造 | 合格气体/底物、菌种或酶、盐、电热 | 合格食材、尾气、废液与热 | 单反应速率不能决定整线产能 |
| 加工与储藏 | 收获批次、加工设备、能源 | 可食用批次、损失、营养变化 | 加工得率、储藏条件、到期与污染 |
| 菜单与人员 | 可用食品、个体营养目标、劳动计划 | 摄入量、营养缺口、代谢排放 | 完整营养与实际摄入，不是简单热量配给 |
| 回收与处置 | 分类废物流、设备和能源 | 合格回收水/养分、未回收废物 | 污染物富集、元素形态、停留时间 |
| 能源与热管理 | 发电、储能、可回收热和设备功率 | 分配电力、储能状态、散热能力 | 峰值、温度等级、共同失效与备用 |
| 运行与维修 | 人员时间、备件、检验结果 | 开停机、隔离和恢复状态 | 每天可操作工时有限；维修件不能自动再生 |

这里的分解来自跨专题工程综合，不意味着每个模块已有可直接编码的完整参数。

## 4. 质量、营养与能量账本

### 4.1 先固定边界

建议同时维护两层账本：

- **整个基地的元素与质量账：** 外部进入、外部排出、内部库存变化；内部循环应相互抵消。
- **单元过程账：** 各化学物种或食品形态的进出、转化和库存变化；反应可能改变物种，但不凭空产生元素。

```math
\Delta M_e = M_{e,\mathrm{external\ in}}-M_{e,\mathrm{external\ out}}
```

其中 `e` 为选定元素或可守恒统计量，统计范围必须包括水箱、气罐、作物、人体、食品、废物等相关库存。对一个局部水箱，不能忽略植物、反应器或代谢过程造成的进出；对完整基地，不应将同一份回收水作为新的外部资源反复累计。

### 4.2 食物库存必须按批次

最少保存：生产方式、品种/菌株、加工状态、鲜干基准、营养组成、质量验收、生产日期、储藏条件、可用量和到期状态。

```math
I_{j,t+1}=I_{j,t}+P_{j,t}+S_{j,t}-C_{j,t}-L_{j,t}
```

- `P`：本时段通过食品质量验收后进入库存的量；
- `S`：外部补给；
- `C`：取出供餐或送入其他加工过程的量；
- `L`：腐败、到期、污染、操作等损失。

若出库后还要烹调，应在下游继续计入损失，不可把出库量直接当人体摄入量。同一批次营养浓度的变化可以单独建模；不得因为热量仍在就保留已经降解的全部维生素。[02：A17]

### 4.3 菜单计算应区别约束性质

用实际可摄入量乘以对应营养浓度，分别评价能量、蛋白质、氨基酸、脂肪酸、纤维、各维生素和矿物质。统一的质量基准是前提。

- 以所选人群标准形成规划目标；不是针对个人的医学处方。
- RDA、AI、EAR、UL 不能互相替代，超过 UL 也不意味着一定有即时毒性，但应触发安全审查。
- 部分营养素需要按长期膳食和人体储备评价，仿真初版可以先输出“供给目标缺口”，**不能把一天低于目标直接模拟为疾病或死亡**。
- 本轮未核验完整的营养素缺乏动力学或低重力人体模型，因此不提供此类健康损伤参数。[02：A13–A18、A20]

### 4.4 闭合率和自给率分别定义

| 指标 | 建议分母和边界 | 注意事项 |
|---|---|---|
| 处理设备水回收率 | 进入该设备的可计量水 | 不代表所有废水都被收集 |
| 系统净补水 | 维持指定库存和运行所需外部新水 | 包括不可回收损失、库存扩张和净反应消耗 |
| 热量本地产出覆盖率 | 同期人员规划热量需求 | 本地产出以验收后的食物为准；库存延迟仍需独立跟踪 |
| 营养素覆盖率 | 对应人群、时段的规划需要量 | 每种营养素单独算；不能用热量替代 |
| 元素回收率 | 定义的可收集废物流中该元素量 | 另记食品/根区可用形态转化率和质量合格率 |
| 外部依赖 | 食品、种源、盐、酶、耗材、零件等补给 | 在火星加工不等于所有原料都来自火星 |

建议同时输出本地来源比例和加工地点，避免把用进口糖发酵得到的食品全部计为“火星资源自给”。

### 4.5 能源不能用食品热值替代

分别记录：电能、不同温度等级的热量、食品可利用能量，以及定义明确时的原料化学能。共同换算为焦耳也不代表可以等价替换用途。

照明、气体处理、电解、反应、搅拌、冷凝、净化、冷藏、检验和待机都应进入相同边界的总能耗。热回收只能抵扣确实匹配的热负荷，不能再次抵扣已经避免的电耗。[02：A12；03：C01-04、C01-11]

### 5.1 一个可复算的照明示例

下列均为情景假设：冠层 PPFD 500 µmol·m⁻²·s⁻¹、每天光照16地球小时、整灯光子效能2.5 µmol/J、冠层截获率0.85。采用02第8节的公式：

```math
\mathrm{DLI}=500\times16\times3600/10^6=28.8\ \mathrm{mol\,m^{-2}\,day^{-1}}
```

```math
E_{\mathrm{light}}=28.8/(3.6\times2.5\times0.85)
\approx3.76\ \mathrm{kWh\,m^{-2}\,day^{-1}}
```

若额外假设每人50 m²种植面积，则照明约188 kWh/人/地球日。**这不证明该面积、光照和任意作物组合能够提供完整饮食**，也未计其他能耗。[02：A03、A12；取值为设计假设]

这种例子的价值在于暴露能源量级，而不是生成一个脱离配方的“每人火星农场标准功率”。

### 5.2 制淀粉的计量结果如何使用

03第8节推导的理想主路线，每kg干淀粉约对应1.63 kg CO2和0.224 kg H2；若氢由电解水提供，整个指定理想边界净耗水约0.556 kg并净产氧约1.18 kg。

这组数值仅用于**配平与单元接口测试**，不代表完整ASAP工厂投料定额。它没有包含全部酶/辅因子制造、损失和下游处理。不能与另一条抽象理想还原路线的0.149 kg H2下限混用。

更不能在完整生命支持模型中一边保留全部净产氧，一边遗漏人员食用这些碳水后产生的代谢氧耗、CO2和水。

## 6. 地图与数据的接入顺序

本轮核验的是数据说明和入口，**尚未下载栅格、抽样像元或完成任意地点的资源评分**。[01：R02、R16–R17]

1. **冻结版本和许可。** 记录产品发布版本、下载日期、原始URL、文件校验和、引用要求和使用条款；不要把所有产品都假定为相同授权。
2. **统一坐标约定。** 保留火星参考体、投影、纬度定义和经度范围；显式处理0–360°E与另一种经度表达方式的转换。
3. **保留NoData。** 在重采样、平均、排序前做掩膜，不把未知资源自动当0。
4. **先按原始尺度筛选。** SWIM像元、源仪器支持尺度和地形DEM尺度各自保留；不要用插值制造更精细的资源信息。
5. **将地点拆成设施节点。** 登陆区、居住/农业区、井场、发电区、废物区可以分开；距离、坡度、运输和管线有成本。
6. **抽取完整季节序列。** 至少比较季节与尘埃情景，而不是仅取全球平均温度或某天峰值日照。MCD是模型，不能标为天气实测。
7. **筛选后再勘查。** 原料成分、冰顶、机械性质和污染物仍需实际勘查；地图筛选不等于矿山验收。

推荐地图属性：`evidence_layer`、`source_resolution`、`depth_class`、`unknown_mask`、`terrain_constraints`、`seasonal_energy`、`transport_distance`、`sampling_needed`。暂不填未经核验的具体基地坐标。

## 7. 可比较的四类情景

以下是为了今后实现模型而提出的实验设计，**本轮未运行这些情景**。

### 7.1 统一的示例任务边界

可从一个6人、400 sol的驻留场景开始。人数、任务长度及以下取值全部是设计假设，不是已批准任务方案：

- 营养先按地球日定义，再显式换算到仿真时间；
- 以2800 kcal/人/地球日作为计算示例，同时试验2400和3200；
- 人员体重按70 kg示例，蛋白质分别检查成人基线和另设的1.2–1.6 g/kg/日工程敏感性条件；
- 全部方案使用相同营养约束、食品质量标准、场址环境和初始资源边界；
- 确需未知工艺参数时，列为假设并输出敏感性结果，不得冒充实测最优解。

每日示例能量需求为16,800 kcal/地球日，但还需完整菜单和实际摄入验证。若模型每步是1 sol，应按88,775/86,400的近似时长比例转换，而不是继续使用16,800作为每sol需求。

### 7.2 方案对照

| 情景 | 食物生产组成 | 回答的问题 |
|---|---|---|
| S0：补给基线 | 储备食品＋小规模鲜食农业 | 不扩建主粮生产时，补给质量、营养衰减、库存和能耗是多少？ |
| S1：农业扩展 | 主粮＋豆类＋油料＋鲜菜，保留储备与强化渠道 | 哪种配方能兼顾营养、电力、工时和收获周期？ |
| S2：混合蛋白 | S1部分蛋白来源由明确菌株及工艺的微生物食品替换 | 是节省资源，还是把负担转移到电解、气体传质和下游加工？ |
| S3：研究性合成淀粉 | 引入参数区间明确的ASAP候选模块 | 哪些酶寿命、能耗、收率阈值改变路线优劣？ |

S3只能用于探索“如果达到某性能，会发生什么”，不能在缺少整线数据时得出“当前已经更优”。S2也须区分实测部分与火星环境外推。

### 7.3 必测的扰动

- 矿水产能低于预期、覆土更深或净化损失更高；
- 照明或环境控制停机，不同生长阶段出现不同损失；
- 一批食品未通过验收，不应继续进入菜单；
- 矿井、温室、反应器共用电源失效，不得按独立故障相乘低估风险；
- 连续低辐照及储能不足，逐时检查电力分配；
- 酶或过滤材料提前耗尽，检验库存而不是只看生产设备；
- 补给延误与作物完整再生长周期叠加；
- 一人或多人不能承担原定农务工时；
- 维生素库存到期而总食物热量仍充足。

扰动幅度先按设计情景设置，后续用实际设备故障和农业批次数据标定；不虚构失效率或概率分布。

## 8. 未来代码的验收用例

以下是待实现模型的测试要求，不是本仓库目前已经通过的程序测试。

| 测试 | 预期行为 |
|---|---|
| sol/地球日换算 | 相同物理时长的累计需求一致，改变时间步不会改变总消费 |
| 鲜重/干重隔离 | 1 kg鲜菜不可直接计作1 kg干碳水或蛋白质 |
| 不可食部分 | 籽粒、秸秆及根等分开，不能同时计入食品与待回收原料 |
| 完整收获周期 | 播种当天不产生稳态粮食；消毒和再播有周转时间 |
| 库存非负 | 缺粮时输出缺口，不允许凭借负库存继续满足需求 |
| 批次质量 | 未合格或过期批次不能进入可食库存 |
| 营养独立约束 | 热量足够但油脂、B12或其他营养不足时不能宣告成功 |
| 回收计量 | 内部循环不增加外部资源总量；总账元素守恒 |
| 未知值处理 | NoData和未公开工艺电耗不会被当作0成本 |
| 子系统容量 | 水、气体、散热或供电不足会限制实际产能 |
| 副产品核算 | 制造产氧和微生物/人员氧耗同时入账，避免重复抵扣 |
| 断电和再启动 | 恢复供电不代表所有作物、菌种或食品立即恢复原产能 |
| 共同失效 | 共享设备停机影响所有依赖模块，不能被冗余统计掩盖 |
| 引用追踪 | 每个用于运行的非假设数字能定位到来源和条件 |

应先验证这些守恒和边界测试，再进行经济性、人口规模或场址排名。

| 优先级 | 问题 | 要补的证据 | 为什么重要 |

## 11. 建议的下一步实际交付

按依赖推进，而不是一次假装补全全部参数：

1. 从本库选择一个明确的示例任务和统一计量口径。
2. 建立人员营养、批次库存和物质守恒的最小模型，先用补给基线测试。
3. 从原始文献提取少量完整的作物配方，逐项注明无法确定的参数。
4. 接入候选场址数据及电力/水情景，再比较农业扩展路线。
5. 获得制造模块足够数据后再引入S2/S3，并开展阈值与敏感性分析。

**完成标准：** 不是生成一个看似精确的火星自给率，而是让每个结果都能回答“输入来自哪里、边界是什么、哪些是假设、出了故障还能撑多久”。
